## 5. Insights and Learnings

- **Read the spike before designing the upgrade.** The spike at `~/projects/vibeacademy/agile-flow-gcp-staging` already implemented Cloud Run + Neon + WIF + revision-tagging previews + rewritten agents + GCP-aware docs. The original ticket plan would have duplicated 80% of this work. The real gaps are workshop-only (multi-project vending, WIF automation, budget caps, runbook) — much narrower scope than the initial plan.

- **Per-PR revision tagging > per-PR services on Cloud Run.** The spike's `EPHEMERAL-PR-ENVIRONMENTS.md` documents why: 1000-services-per-region quota, IAM/secret duplication, slow cleanup, lossy log history. Tags solve all four. This is a pattern to keep — likely worth promoting to the upstream pattern library when GCP support lands there.

- **Neon branching is faster than Supabase branching for previews.** Spike notes ~1 second copy-on-write branch creation vs Supabase's branch-create latency. If upstream ever adds a "Neon as DB option" alongside Supabase, this is the lever.

- **Multi-fork distribution is the real strategic question.** A second fork (AWS) is plausible if corporate workshops continue. The four options (overlay model, monorepo+starters, cherry-pick automation, plugin-in-one-repo) have different cost/scalability profiles. Captured in `docs/research/multi-fork-distribution-strategy.md`. Recommendation: Option 3 for next workshop, Option 2 medium-term, never Option 4.

- **Single board, multi-repo scales until ~3 active forks.** Adding `agile-flow-gcp` to board 13 was a 30-second config change. The "noise" problem doesn't bite until multiple forks have active sprints simultaneously. Revisit when AWS fork goes live.

- **Issue-creation as a planning tool works only when scoping is settled.** The session spent significant time iterating on fork strategy and workshop architecture before any tickets were created. Trying to file tickets earlier would have produced wrong-shaped tickets that needed rewriting. The plan-first instinct paid off again (mirrors 2026-03-20's takeaway).
