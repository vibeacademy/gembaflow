## 5. Insights and Learnings

- **The 14th file**: When removing a capability (like an MCP tool name), always search for *detection scripts* that grep for the old name — not just files that *use* the capability. `verify-agent-restrictions.sh` wasn't in the original plan because it doesn't use MCP, it just detects the deny rule. Review caught it.

- **Single PR for coupled changes**: 6 tickets, 1 PR was the right delivery unit. The intermediate states (e.g., docs referencing MCP while config doesn't have it) would have been inconsistent and created noise in reviews.

- **Plan-first workflow paid off**: Writing the plan as a reviewable markdown doc before creating issues or code caught the wrong-repo mistake early. The workflow impact analysis section also made the "why" clear for the PR description.
