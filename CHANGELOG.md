### Added

- **CI fleet gated behind `.github/workflows/_detect-changes.yml` — docs-only PRs skip ~6 of 7+ jobs (incl. ~5min Render preview compute)** — new reusable workflow returns a single `should-run-ci` boolean output computed via `dorny/paths-filter@v3` against a positive allowlist (`app/`, `components/`, `lib/`, `worker/`, `types/`, `__tests__/`, `scripts/`, `.claude/{agents,commands,skills,hooks}/**`, `.gembaflow-{meta,overrides,version,config.example.json}`, `.github/workflows/**`, validation toolchains). Anything outside the allowlist is treated as docs-only; CI fleet skips. Every job except `lint` (markdown lint, ~5s, runs UNGATED so docs-only PRs still catch broken tables / MD038 / MD049) and `detect` (the gate itself) inherits the gate via `needs: detect` + `if: needs.detect.outputs.should-run-ci == 'true'`. Touches `.github/workflows/_detect-changes.yml` (new), `ci.yml`, `auto-review.yml`, `preview-deploy.yml` (8 jobs gated total). **`.claude/{agents,commands,skills,hooks}/**` are validated config — NOT docs** — `lint-agent-policies`, `test`, and `template-cleanliness` jobs invoke validators against these paths; the carve-out keeps a malformed agent (e.g. #488's YAML bug) from merging green via the docs-only path. Skipped-as-passing semantics correctly cited (GitHub May 2022 status-check change); branch protection still resolves green on docs-only PRs. Job names preserved across the board so branch-protection rules pinning specific check names are unaffected. `auto-review.yml`'s "Trigger PR Review" job now also skips on docs-only PRs — operators wanting an agent review on a docs PR invoke `/review-pr <N>` manually. `docs/CI-CD-GUIDE.md` § "Active by Default → CI" gains a "Docs-only PR gate" subsection documenting the allowlist + carve-outs. Closes #491. (#485)

- **`scripts/deploy-status/interface.mjs` — provider-plugin dispatcher for drain step 9 (deploy-wait)** — closes the abstraction gap that blocked non-Render downstream forks from using `/drain`. The dispatcher carries the full interface contract as a header docblock — adapters conform by matching the invocation shape (`node <adapter> <commit-sha>`), the env-var convention (adapter-private), and the JSON envelope. Smoke-tested locally: render plane invokes `render-deploy-status.mjs` and forwards its output; unknown plane (e.g. `fly`) emits clear hint listing supported; cloud-run plane (adapter not yet installed) emits unavailable with expected-path hint; no-sha errors cleanly with usage on stderr. ### Fixed

- **`/drain` pre-flight step 4 expands to detect all three manual-install artifacts with clear-cause errors — closes the discoverability gap that made framework-design manual-install look like a propagation bug** — `.github/workflows/agent-merge.yml`, `.github/workflows/drain-merge-bridge.yml`, and the `safety:*` label vocabulary are all manual-install per `docs/drain-customization.md` (workflow files aren't in `syncDirectories` by intentional design — forks customize their own workflows without sync clobber). Previously, pre-flight step 4 only checked `agent-merge.yml`; missing `drain-merge-bridge.yml` failed deep inside the per-iteration cycle, and missing labels failed only at step 6 with an opaque "unclassified ticket" message that hid the actual cause (the label vocabulary itself doesn't exist on the fork). Restructured step 4 into a "Manual-install drain artifacts" cluster with three sub-checks (`4a` agent-merge.yml, `4b` drain-merge-bridge.yml, `4c` safety:* label vocabulary), each with a clear-cause STOP message pointing to `docs/drain-customization.md` § "Bridge workflow installation" for the workflow files OR to the new `bash scripts/setup-safety-labels.sh` helper for the labels. The framework's design — workflow files are deliberately out of `syncDirectories` so forks can customize freely — is unchanged; this fix is purely the discoverability + ergonomics layer on top. Fork impact: every fork that runs `/drain` without completing the manual-install steps gets a precise pointer to the doc or the one-command label-setup helper, instead of opaque "workflow not found" or "all your Ready tickets are unclassified" errors. Surfaced via downstream-report #492 from `feature-x/reticle`, whose operator misread the missing artifacts as a framework propagation bug; the gap was actually discoverability + setup-helper ergonomics. (#494)

- **`/drain` pre-flight detects unsubstituted `{{...}}` placeholders before the gh CLI fails opaquely — closes the cause-of-confusion that made stale-config-on-fork look like a framework bug** — `.claude/commands/drain.md` ships with the four canonical placeholders (`{{org}}`, `{{board.id}}`, `{{bot.worker}}`, `{{bot.reviewer}}`) directly in pre-flight steps 1, 3, and 5; the substitution to fork-specific values happens fork-side via `scripts/substitute-config-placeholders.sh` (shipped in #416 / v1.5.0). If the substitution hasn't run on a fork — because the fork was bootstrapped pre-1.5.0, the operator skipped `/bootstrap-workflow` step 7, or a `/upgrade` re-introduced placeholders that weren't re-substituted — the existing pre-flight failed opaquely with `account not found` from `gh auth status {{bot.worker}}` and `gh: 404` from `gh project view {{board.id}}`, hiding the real cause. New Step 0 (RUNS FIRST, before any other check) runs `bash scripts/substitute-config-placeholders.sh --check`; on exit 0 (no placeholders found) it proceeds to step 1, on exit 1 with `.gembaflow-config.json` populated it auto-runs the substitution and proceeds, and on exit 1 with config missing or incomplete it STOPs with a clear error message pointing to `/bootstrap-workflow` step 7 and the `.gembaflow-config.example.json` schema. The substitution mechanism, the `.gembaflow-overrides` default that protects substituted `drain.md` from `/upgrade` clobber, and the customer-facing checklist in `docs/drain-customization.md` were all already in place; this fix is purely the pre-flight detection layer that converts opaque failures into a self-explaining stop. Fork impact: every fork on a stock drain.md gets either auto-recovery (if their config is populated) or a clear-cause stop (if not) — replacing the prior opaque gh-CLI failure. Surfaced via downstream-report #492 from `feature-x/reticle`, whose operator originally read the `{{...}}` strings as a load-bearing bug; they were actually the signal that the operator's fork hadn't run the substitution pass. (#493)

- **`scripts/report-issue.sh` accepts the bare-slug `upstream` form that `template-sync.sh` writes — closes the producer/consumer regex disagreement that blocked `/report-issue` on every freshly bootstrapped fork** — `template-sync.sh` writes `.gembaflow-version`'s `upstream` field as a bare slug (e.g. `vibeacademy/gembaflow`) but `report-issue.sh` required a full GitHub URL (`github\.com[:/]([^/]+/[^/]+)$`), so any fork on a stock `.gembaflow-version` hit `ERROR: Cannot parse GitHub repo from: vibeacademy/gembaflow` and exited before any issue was filed. Fix is consumer-side only per the ticket guardrail: adds a second `elif` arm matching `^([^/[:space:]]+/[^/[:space:]]+)$` as a fallback when the URL/SSH regex misses, with whitespace explicitly excluded from each slug token so junk like `not a valid upstream string` still fails loudly into the existing error branch. Existing URL form, SSH form (`git@github.com:org/repo`), and URL-with-`.git` suffix all continue to parse through the unchanged first arm — zero behavior change for forks that had hand-edited `.gembaflow-version` slug→URL as a workaround. Error message updated to name both accepted shapes (`https://github.com/org/repo` and bare slug `org/repo`). `template-sync.sh` is intentionally NOT touched — producer-side normalization is a larger surface change deferred to a follow-up. `scripts/report-issue.test.sh` extends from 5 to 9 scenarios (`make_workspace` now takes an optional `upstream` arg): (f) bare-slug acceptance — regression coverage for this fix; (g) SSH-form upstream still parses — guards against unintended first-arm change; (h) URL-with-`.git`-suffix still parses — guards the existing `.git`-strip step; (i) garbage upstream errors loudly with the "Cannot parse GitHub repo from:" marker — guards against the elif silently catching invalid shapes. 11 → 20 PASS assertions, all green under `CI=1`. Fork impact: every fork bootstrapped via `/upgrade` (which is every fork, including `vibeacademy/gembaflow-gcp` whose own `.gembaflow-version` ships slug form) picks up the fix on next template-sync and can run `/report-issue` without operator hand-editing — surfaced via downstream-report #492 from `feature-x/reticle`, whose operator described editing `.gembaflow-version` as a workaround "so I could file *this* report." (#323)

- **YAML frontmatter on all 14 project-level agents — `<example>` blocks were embedded directly inside the frontmatter, breaking the parse and silently dropping every agent in fresh sessions** — every file in `.claude/agents/` (the product-variant roster) and `.claude/commands/bootstrap-agents/platform/` (the platform-variant templates installed by `/bootstrap-agents --variant platform`) had `<example>` and `</example>` lines sitting between bare `description:`, `model:`, and `color:` keys. The `<example>` opening tag is not a valid YAML key (no `:` follows), so a strict YAML parse failed on the whole frontmatter — Claude Code's agent loader rejected the file and the Task tool reported `Agent type 'swarm-planner' not found` (and the same for `github-ticket-worker`, `pr-reviewer`, `quality-engineer`, `system-architect`, `devops-engineer`, both `agile-*` agents, and all six platform variants — `framework-architect`, `platform-backlog-prioritizer`, `release-engineer`, plus the platform-flavored `github-ticket-worker`, `pr-reviewer`, `swarm-planner`). Symptom in practice: `/swarm` was unrunnable end-to-end on a fresh fork (Phase 1's `Task(subagent_type: "swarm-planner")` errored before any brief was generated); `/work-ticket`, `/review-pr`, `/groom-backlog`, and any other slash command that routes through `.claude/agents/*.md` hit the same wall. Fix wraps each `description:` value in a `|-` block scalar with the `<example>` blocks indented two spaces, so the examples sit inside the description as preformatted text. All required keys (`name`, `description`, `model`, `color`) survive cleanly, the example payload reads identically to the model, FRAMEWORK markers are untouched, and the hybrid-agent contract holds (the frontmatter is in the framework-owned region so `/upgrade` propagates the fix to forks without disturbing per-fork specialization after `<!-- FRAMEWORK:END -->`). Verified with `yaml.safe_load` against all 14 files. Surfaced by the `vibeacademy/gembaflow-site` 2026-06-14 `/swarm 247` session — root cause was one layer below the reporter's "agent not in registry" diagnosis. (#488)
## [1.5.0] - 2026-06-13

**Major release. Headline pairing: `/drain` ships AND the upgrade pipeline can actually deliver it.** Lands the four-ticket drain port (T1–T4) plus the keystone self-healing-sync fix (#371) that closes the long-standing upgrade-pipeline gap. 28 PRs ship between v1.4.0 (2026-06-01) and v1.5.0 (2026-06-13).

**Migration: every existing fork needs a one-time manual refresh of `scripts/template-sync.sh` and `scripts/lib/overrides.sh` on first `/upgrade` to v1.5.0** — see the v1.5.0 GitHub Release notes § "Propagation note" for the exact commands. Fresh forks (provisioned after v1.5.0) get the self-heal automatically. Subsequent runtime-protected fixes propagate without manual intervention.

**Branch-protected forks must also add `json-validate` to their required-status-checks list on the `main` ruleset** (#471 split the `version-parity` umbrella job). Existing `version-parity` entry stays.

Full release narrative + per-PR detail: [v1.5.0 release notes](https://github.com/vibeacademy/gembaflow/releases/tag/v1.5.0). Per-entry detail below.

### Added

- **`scripts/template-sync.sh` self-heals runtime-protected files after the sync loop — closes the self-upgrade gap** — until now, bug fixes landed in `scripts/template-sync.sh` or `scripts/lib/overrides.sh` (the two `RUNTIME_PROTECTED_PATHS` entries) could not reach forks via the normal sync. The main sync loop correctly skips these files because the running script cannot safely overwrite itself mid-execution; but that meant every fork bootstrapped before #361 (package.json auto-bump) hit red CI on its first `/upgrade` because the bumped-script was stuck on the pre-fix version. New post-sync-loop block in `template-sync.sh` (between the main loop and `WORK_DIR` cleanup) re-copies each runtime-protected file from the already-extracted release tarball IF (a) the local file differs from the tarball version AND (b) the path is NOT in `.gembaflow-overrides`. The currently-running script process is unaffected — it's in memory; only the on-disk file is updated, so the next `/upgrade` invocation reads the refreshed code. Refreshed files appear in `FILES_CHANGED`, ride the same sync PR, and surface in a new `> [!IMPORTANT] Runtime-protected files refreshed` callout on the PR body. Operators reviewing the sync PR see the refresh explicitly and can decide. `scripts/template-sync.test.sh` gains 2 new scenarios (Scenario 9 positive: both runtime-protected files refresh + PR body callout; Scenario 9b negative: file listed in `.gembaflow-overrides` is preserved while the non-overridden file still refreshes) plus updated assertions on Scenario 1 to reflect the post-#371 contract — 48 total test assertions PASS. Fork operators bootstrapped before #361 will see this PR's sync update both `template-sync.sh` and `overrides.sh` cleanly on their first `/upgrade` to this version; subsequent fixes to either file propagate normally. - **`features/` directory added to `syncDirectories`** (#362). Downstream forks bootstrapped before the rebrand had stale `features/*` files referencing `.agile-flow-version` that `/upgrade` never touched, causing the BDD suite to fail post-sync. Future `/upgrade` runs now refresh these files. (#364)
- **`.claude/agents/*.md` now classified as `hybrid` with FRAMEWORK markers** (#363). Previously `bootstrap-agents` and `template-sync.sh` silently contradicted each other — every sync wiped out project-specific agent specialization. Now `template-sync.sh` only updates content between `<!-- FRAMEWORK:START -->` and `<!-- FRAMEWORK:END -->` markers; user-supplied specialization outside markers is preserved. (#366)

### Changed

- **CI job renamed `typecheck` → `version-parity`** (#361). The job had been misleadingly named `typecheck` — it never ran `tsc`, only the version-parity check. The real TypeScript `tsc --noEmit` lives in the `node` job and is unchanged.

  **⚠ Branch protection action required for consumers**: if you have a fork with branch protection that mirrors upstream, the required-status-check named `typecheck` now needs to be renamed to `version-parity` in your ruleset. Otherwise sync PRs against your fork will block on a check that no longer exists.

### Added

- **`bootstrap-agents` skill updated** with one-shot migration logic: when run on a legacy agent file (no markers), wraps the framework persona content in markers and appends project specialization after. Forks that ran `bootstrap-agents` before this release should re-run it once to gain marker protection. (#366)

### Migration notes

After `/upgrade` against this release:

- **Existing `.claude/agents/*.md` files without `<!-- FRAMEWORK:* -->` markers are preserved entirely** (preserve-and-warn behavior). The sync PR includes a `[!WARNING]` callout listing those files and recommending `/bootstrap-agents` to gain marker protection.
- **`features/*.{py,feature}` files** with `.agile-flow-version` literals (a leftover from pre-rebrand bootstrap) will be replaced by the clean upstream versions. Forks that have customized their own feature tests should add `features/<file>` to `.gembaflow-overrides` to protect them before the sync.
- **Sync PRs land green on CI**. The `version-parity` job verifies `.gembaflow-version` and `package.json` agree; `template-sync.sh` writes both, so they always do.

**Phase 0.5 of the agile-flow → Gemba Flow rebrand.** This release is the critical-path enabler for the upcoming repo rename. Active forks **must** run `/upgrade` against this release before the rename happens — without it, `/upgrade` will silently break the moment the rename's 301 redirect lands.

### Added

- **`upstream` field in `.agile-flow-version`** — Downstream variant forks (e.g. `agile-flow-gcp`, future `agile-flow-aws`) can now declare their own upstream repo for `/upgrade` syncing. Falls back to the hardcoded `vibeacademy/agile-flow` default when absent. Accepts bare `owner/repo`, full HTTPS URL, or git URL forms — all normalized internally. (#342, supersedes #204)
- **Pattern #28** in `docs/PATTERN-LIBRARY.md` — "GitHub Actions: Workflow Pushes With `GITHUB_TOKEN` Don't Re-Trigger CI". Documents the auto-fix workflow gotcha, the lint-as-CI-check resolution, and the PAT-based escape hatch. (#338)
- **Canonical PAT scope set** documented in `.claude/README.md` with per-scope rationale. Includes a `gh auth refresh` remediation block for existing reviewer PATs missing the `project` scope. (#340)

### Changed

- **`/upgrade` (template-sync.sh) is now redirect-safe.** The `curl` call to the GitHub releases API uses `-L` to follow 301 redirects, so it continues working transparently when an upstream repo is renamed. Adds a `vibeacademy/gembaflow` fallback that triggers only when the primary returns 404, with a single informational stderr line. (#342)
- **Pre-flight checks** in `/create-ticket`, `/quick-fix`, `/work-ticket`, `/bootstrap-workflow` now use `gh auth status` + `gh repo view --json nameWithOwner` instead of the (since-removed) MCP GitHub server probe. (#339)
- **Account-switch hook** (`.claude/hooks/ensure-github-account.sh`) now routes `gh pr review` and `gh pr comment` to the reviewer account in addition to `gh pr create` → worker. Routing is intentionally narrow: `gh issue create`, `gh issue comment`, and `gh project item-*` are NOT auto-routed (command patterns can't reliably distinguish worker from reviewer context). Slash commands are responsible for explicit `gh auth switch` when they need a specific account. (#340)
- **Setup script** (`scripts/setup-accounts.sh`) now prints required PAT scopes inline at paste time, including the `gh auth refresh` upgrade command for existing reviewer PATs. (#340)

### Removed

- **`.github/workflows/auto-fix.yml`** — auto-fix-via-`GITHUB_TOKEN` is fundamentally broken (GitHub deliberately suppresses workflow re-triggers from `GITHUB_TOKEN`-signed pushes, leaving PRs at `BLOCKED` until a human pushes a no-op commit). Lint coverage is preserved via the existing `ci.yml` ruff/eslint jobs; pre-push hooks in `scripts/hooks/` provide local-dev auto-fix UX. See Pattern #28 for the full gotcha writeup. (#338)

### Fixed

- **Stale doc references to `auto-fix.yml`** in `docs/CI-CD-GUIDE.md`, `docs/DISTRIBUTION.md`, `docs/LEAN-PRINCIPLES.md` — the workflow table row, dedicated section, distribution table row, and "CI auto-fix" waste-elimination claim are all corrected. `LEAN-PRINCIPLES.md` now correctly identifies pre-push lint hooks (rather than the deleted CI auto-fix) as the waiting-waste mitigation. (#338)
