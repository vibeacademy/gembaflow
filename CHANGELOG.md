- **bd JSON hygiene — `--limit 0` + sanitize guards across every skill/command bd pipeline, gotchas 9–10, drafted upstream reports, renderer hardening (post-cutover follow-ups, phase 1/2)** — two bd 1.1.0 quirks found live at the meta cutover and acceptance drain (epic #574 post-completion): (1) intermittent **raw control characters inside `--json` output** — a literal tab carried over from an issue body broke a `jq` gate, and the nastiest mode is silent: a failed parse makes absence checks *pass*; (2) **`bd ready` silently caps at 100 rows** with only a stderr advisory — invisible exactly when stderr is separated as it must be — so 13 of 113 ready beads vanished from every bare `bd ready --json` snapshot. **The countermeasure lands once, canonically**: `docs/BEADS-CONVENTIONS.md` § "Script conventions" gains item 3 (bd JSON hygiene — `--limit 0` on enumerations; capture to a file with stderr separated and sanitize the control chars before `jq`, files-not-shell-variables; check jq's exit status so a parse failure never reads as an empty result), and every bd-JSON pipeline in skill/command/agent text — ~45 sites across `/drain` (incl. the load-bearing snapshot pipeline, now shown in full file-based form), `/work-ticket`, `/swarm`, `/review-pr`, `/groom-backlog`, `/sprint-status`, `/doctor`, `/log-session`, `/validate-memory`, `/check-milestone`, `/create-ticket`, `/bootstrap`, `/bootstrap-workflow`, the worker/prioritizer/PM agents, the platform bootstrap-agent templates, and `docs/PATTERN-LIBRARY.md` — now carries `--limit 0` and references the convention instead of restating the incantation. **Gotchas 9–10** are documented at point-of-use in `docs/BEADS.md` (new § "bd 1.1.0 JSON output quirks", continuing the downstream-report §4 numbering). **Both quirks are drafted as upstream bug reports** in new `docs/bd-upstream-reports/{control-chars-in-json,ready-default-limit}.md` (title, version, minimal repro, expected vs actual, impact, workaround) — **NOT filed**: filing on gastownhall/beads is an operator decision, stated in each file's header. **Renderer hardening**: `scripts/lib/boards/data.mjs` gains exported `parseBdJson()`, which strips control chars (except `\n`/`\r`) before `JSON.parse` so one bad issue body no longer silently blanks the boards (the `--check` shape validator catches schema drift, not character drift), and the internal `bd ready` call now passes `--limit 0` (readyIds and ready-carried notes truncated on >100-bead trackers). As a safety net, `scripts/template-sync.sh` now detects the fresh-fork placeholder case (`version == "0.1.0"` with `installedAt` already stamped) and short-circuits: it writes the latest tag into the manifest locally and exits 0 without generating a sync PR. Legitimately-behind forks (e.g. `version: 1.2.0`) still sync normally. (#382)

### Fork-maintained files you must update

None required for this release. v1.3.1 introduces no synced behavior change that's gated on fork-side counterparts being updated:

- No CI check names renamed.
- No backward-compat shims removed.
- No dotfile renames.
- No env var renames.

The fresh-fork fix lives entirely in `bootstrap.sh` (a one-time script run on initial install) and `scripts/template-sync.sh` (which has its own propagation behavior — see below).

### Propagation note (read this if you maintain a fork)

The `template-sync.sh` portion of this fix lives in a **runtime-protected** file (a script can't safely overwrite itself mid-run). Existing forks will NOT pick up the placeholder short-circuit via `/upgrade` until [`#371`](https://github.com/vibeacademy/gembaflow/issues/371) (self-upgrade gap for runtime-protected scripts) is fixed.

**Concretely:**

- **Fresh forks** created from this release onward: get the fix immediately via the `bootstrap.sh` path. No no-op `/upgrade` PR.
- **Existing forks** (already past initial bootstrap): keep behaving as before — first `/upgrade` after this release still generates a sync PR that bumps `version` plus any other framework deltas. Once `#371` ships, runtime-protected scripts will refresh out-of-band and existing forks pick up the short-circuit.

If you want existing forks to benefit immediately, manually refresh `scripts/template-sync.sh` from this release's tarball (the workaround we documented for `#371`).
